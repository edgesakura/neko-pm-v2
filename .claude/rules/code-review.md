# Code Review Rule

## 実装後のたぬきレビュー（必須）

3ファイル以上の変更、または新機能追加時は **実装後にたぬき（Codex）レビューを実施** する。

### フロー

```
実装完了 → git diff で差分確認 → codex-agent に投げる → 指摘を反映
```

### レビュー依頼テンプレート

codex-agent に以下の観点でレビューを依頼:

1. 設計の穴・エッジケースの見落とし
2. パフォーマンス・セキュリティ問題
3. エラーハンドリングの適切さ
4. 並行アクセス・スレッドセーフティ
5. 外部 API 呼び出しパターンの妥当性

### 指摘レベルと対応

| レベル | 対応 |
|--------|------|
| Critical | 必ず修正してから commit |
| Warning | 原則修正。理由付きで先送り可 |
| Info | ご主人判断で取捨選択 |

### スキップ条件

- 1-2行の typo / 設定値変更
- ドキュメントのみの変更
- ご主人が明示的にスキップ指示した場合
